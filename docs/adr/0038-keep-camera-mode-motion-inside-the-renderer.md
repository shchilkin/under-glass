# Keep camera mode motion inside the renderer

The renderer owns one deterministic Camera Mode Transition between the canonical isometric and top poses so every integration retains the same spatial continuity and motion character. The requested mode becomes the public target immediately while interpolation remains internal transient state and does not add a renderer lifecycle status. Initial rendering, Poster capture, and hydration apply the Opening View immediately; motion starts only after a later target-mode change. Transition time follows elapsed wall-clock time, so a Viewer returning from a background pause presents the current target instead of replaying stale motion; viewport changes recompute framing and label projection while preserving the current target and transition progress. Hosts may explicitly request an immediate switch for programmatic scenarios and choose the named `responsive` or `spring` Camera Motion through the renderer option. The future React Viewer maps the same choice to a prop. `responsive` is the default. Arbitrary duration, easing, interruption behavior, and reduced-motion handling are not stored in the Visualization or exposed as host configuration; this keeps transient presentation out of the domain contract while preserving a deliberate, supported choice of motion character.
